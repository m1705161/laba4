# CDC и Debezium: захват изменений из PostgreSQL

CDC (Change Data Capture) — это механизм, позволяющий перехватывать изменения, происходящие в операционной базе данных, и доставлять их в другие системы практически в реальном времени. Вместо того чтобы периодически перечитывать всю таблицу целиком, мы получаем только изменившиеся строки.

## Зачем нужен CDC

При построении lakehouse данные из операционных БД (PostgreSQL, MySQL) должны попадать в озеро. Наивный подход — перечитывать всю таблицу по расписанию. Это медленно, нагружает источник и даёт большую задержку. CDC решает проблему: мы следим за логом изменений и доставляем только дельту.

## Как работает Debezium

Debezium — это популярный инструмент CDC с открытым исходным кодом. Он подключается к источнику, читает его журнал изменений и превращает их в события:

- для PostgreSQL Debezium использует логическую репликацию (WAL — write-ahead log);
- для MySQL — binlog;
- для MongoDB — oplog.

Каждое событие содержит состояние строки до и после изменения, а также тип операции: insert, update или delete. Эти события Debezium публикует в Kafka, откуда их могут читать потребители — например Spark, который применяет изменения к таблице в lakehouse.

## Типичный конвейер

Типичный конвейер CDC выглядит так: PostgreSQL → Debezium (Kafka Connect) → Kafka → Spark Structured Streaming → таблица Iceberg. Debezium следит за таблицей-источником, пишет события в Kafka, а Spark-джоб читает поток и поддерживает целевую таблицу (часто SCD2) в актуальном состоянии.

Такой подход позволяет держать озеро почти синхронным с источником, не перегружая его полными перечитываниями и не пропуская промежуточные состояния строк.
